# Noter til mundtlig eksamen

Dette dokument samler korte noter, som jeg kan bruge til at forklare mit portfolio til eksamen.

## Kort start

Jeg vil starte med at præsentere mit portfolio. Portfolioet viser mine projekter fra 1. semester og forklarer min proces, min læring og mine refleksioner.

## Overordnet om sitet

- Portfolioet er bygget med HTML, CSS og JavaScript.
- Sitet har en forside, en portfolio-side, en proces-side og en om mig-side.
- Formålet er at vise både færdige produkter og processen bag.
- Jeg har arbejdet med responsivt design, så sitet fungerer på mobil og desktop.

## Tema 2 - Mobilesite / desktop-udbygning

Dette projekt viser mit grundlæggende arbejde med HTML og CSS.

Det jeg kan fortælle:

- Opgaven var at arbejde videre på mobilsitet, så det også virkede på desktop.
- Sitet består af 5 sider og følger udleveret wireframe/layoutdiagram.
- HTML blev brugt til struktur.
- CSS blev brugt til layout, typografi, farver og afstande.
- Jeg brugte noindex og arbejdede med validering.
- Projektet blev fundamentet for de senere projekter.

## Tema 3 - OBBG sandkassesite / emnesite

OBBG.dk er mit sandkasse- og emnesite. Projektet handler om et fiktivt digitalt koncept, hvor jeg arbejdede med selvvalgt emne, 3 designassociationer, centralt budskab, brugerrejse, styletile, storyboard, billeder og kodet løsning.

Det jeg kan fortælle:

- Jeg startede med at definere emne, budskab og designassociationer.
- Jeg arbejdede med brugerrejse, moodboard, styletile, wireframes og prototype i Figma/FigJam.
- Jeg skulle tænke over hero-elementets storytelling: motiv, bevægelse og sekvens.
- Jeg brugte visuelle elementer og tekst til at bygge et samlet koncept.
- Jeg lærte, at et emnesite skal have sammenhæng mellem budskab, billeder, overskrifter og brugerrejse.

Vigtig refleksion:

- Hvis jeg arbejdede videre, ville jeg dokumentere endnu flere iterationer af billeder og AI-prompts.
- Jeg ville også arbejde mere med accessibility og troværdighed.
- Projektet lærte mig, at et digitalt koncept skal kunne forklares både visuelt, teknisk og kommunikativt.

## Tema 4 - Royal Click Fighter

Royal Click Fighter er mit animations- og spilprojekt.

Det jeg kan fortælle:

- Spillet bruger JavaScript til interaktion.
- Events bruges til klik.
- Variabler holder styr på point, liv og tid.
- Feedback viser brugeren, hvad der sker.
- Jeg lærte, at JavaScript kræver logisk struktur.

## Tema 5 - Virksomhedssite/redesign / Bird Bar

Bird Bar er mit virksomhedssite-projekt. Det er et gruppeprojekt, hvor vi arbejdede med redesign, virksomhedens identitet, målgruppe, indhold og visuelle udtryk.

Det jeg kan fortælle:

- Vi skulle arbejde med teamkontrakt, SCRUM og Trello.
- Vi skulle researche brand, målgruppe, produkter/services, struktur, brugerrejser og formål.
- Vi lavede moodboard, wireframes, prototype og indholdsoversigt.
- Vi skulle producere billeder og integrere indhold som animation/video/motion graphics.
- Sitet skulle kodes mobile-first med HTML, CSS og JavaScript uden frameworks.
- Testkravene omfattede bl.a. 5-sekunders test, tænke-højt-test, Likert, heuristisk evaluering og Lighthouse.

Vigtig refleksion:

- Et virksomhedssite skal have tydelig sammenhæng mellem afsender, målgruppe og design.
- Jeg lærte, at gruppearbejde kræver kommunikation og rollefordeling.
- Hvis jeg arbejdede videre, ville jeg dokumentere test og mine egne bidrag mere præcist.

## Teori jeg skal kunne forklare

### HTML
HTML bruges til struktur. Det bestemmer sidens indhold og opbygning.

### CSS
CSS bruges til det visuelle udtryk. Det styrer layout, farver, typografi og responsivt design.

### JavaScript
JavaScript bruges til interaktion. Det kan reagere på brugerens handlinger.

### UX
UX handler om brugeroplevelsen. Det handler om, om brugeren forstår og kan bruge løsningen.

### UI
UI handler om det visuelle interface. Det er farver, knapper, typografi, layout og visuel identitet.

### Responsivt design
Responsivt design betyder, at sitet fungerer på forskellige skærmstørrelser.

### Brugertest
Brugertest bruges til at finde ud af, om en løsning giver mening for brugeren.

## Mulige spørgsmål fra censor

### Hvorfor har du valgt denne struktur?
Jeg har valgt en enkel struktur, fordi brugeren hurtigt skal kunne finde projekter, proces og information om mig.

### Hvad har du lært mest?
Jeg har lært, at et website ikke kun handler om udseende, men også om struktur, brugerforståelse, indhold og teknisk opbygning.

### Hvad ville du forbedre?
Jeg ville dokumentere min proces mere løbende, teste tidligere og arbejde mere systematisk med accessibility.

### Hvordan bruger du billederne?
Billederne fungerer som dokumentation. De viser research, wireframes, prototype, færdigt produkt, kode og test.

### Hvordan hænger projekterne sammen?
Projekterne viser en udvikling fra grundlæggende HTML og CSS til emnesite, JavaScript, redesign, brugertest, gruppearbejde og refleksion.
